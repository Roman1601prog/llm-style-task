# Адаптация новостей под два Telegram-стиля

Модель: `Qwen/Qwen2.5-1.5B-Instruct`, ревизия `989aa7980e4cf806f80c7fef2b1adb7bc71aa306`. Два независимых QLoRA-адаптера обучены через Transformers/PEFT на Tesla T4 в Google Colab. Для каждого стиля выделено 20 train- и 5 validation-пар; пять финальных исходников не участвовали в обучении. Гиперпараметры и чат-шаблон зафиксированы в `RESULTS.md` и `artifacts/train_type*.json`.

## Результаты

- `outputs_type1.txt` и `outputs_type2.txt`: по пять исходных финальных генераций.
- `RESULTS.md`: архитектура, три сравнения baseline/prompt-only/LoRA, оценки, ограничения, время и план vLLM для GPU с 24 GB.
- `REVIEW.md`, `REVIEW_SUMMARY.md`: оценки 30 validation-ответов. Средняя структура улучшилась с 1.6/5 до 4.3/5, стиль — с 1.3/5 до 2.5/5. Фактические искажения остались в 4 из 10 ответов каждого режима; улучшение достоверности не подтверждено.
- В десяти финальных постах отмечены три существенные фактические ошибки и китайский лид в одном ответе. Текущие результаты требуют редакторской проверки; подробно разобраны в `RESULTS.md`.

После сброса Colab часть текстовых записей восстановлена из сохранённых REVIEW и TXT; неизвестная телеметрия оставлена `null`. Происхождение записей описано в `RECOVERY.md`. Веса, параметры обучения и исходные baseline/prompt-only-журналы сохранены.

## Воспроизведение

Работайте в отдельной копии проекта: подготовка данных, генерация и составление отчёта записывают файлы с результатами.

1. Скачайте репозиторий через **Code → Download ZIP**.
2. Откройте `style_task_colab.ipynb` в Google Colab, выберите среду с NVIDIA GPU и загрузите ZIP в первую ячейку.
3. Выполняйте ячейки по порядку: установка → подготовка и проверка данных → baseline → prompt-only → обучение двух адаптеров → validation → оценка → test → отчёт.

`executed_colab.ipynb` содержит сохранённый ход исходной работы, в том числе промежуточные ошибки загрузки и восстановления. Финальные файлы проверены отдельно при упаковке. Инструкция для Windows и браузера — `GUIDE_RU.md`; сводка проверки комплекта — `PACKAGING_CHECK.md`.

## Обученные веса

Полный **`submission.zip`** содержит оба исходных `adapter_model.safetensors` и весь проект в папке `llm-style-task/`. Этот архив предназначен для приложения к **GitHub Release** либо отдельной передачи проверяющему. После скачивания распакуйте его; файлы адаптеров находятся в `llm-style-task/adapters/type1/` и `llm-style-task/adapters/type2/`.

В **`github_upload.zip`** бинарные веса исключены для загрузки через браузер. Его распакованное содержимое загружается в корень репозитория. Базовые веса Qwen скачиваются по закреплённой ревизии и в архивы не входят. Промежуточные checkpoints и Python-окружения исключены из экспорта.

## vLLM

План, расчёт памяти и проверка под нагрузкой — `PRODUCTION.md`; команда с двумя LoRA — `serve.sh`. Запускать в отдельной Linux-среде с зависимостями из `requirements-serve.txt`. Для расчёта выбраны 15 активных последовательностей и 4096 токенов суммарно на промпт и ответ. vLLM-сервер и нагрузочный тест на GPU с 24 GB в рамках этого эксперимента не запускались.
