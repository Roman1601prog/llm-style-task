# Выполнение тестового задания на Windows через Google Colab

Весь сценарий рассчитан на твой ноутбук с Windows. Модель обучается и генерирует тексты на удалённой NVIDIA GPU в Google Colab. На ноутбуке используются браузер, Проводник и текстовый редактор. Ubuntu, WSL, Python и CUDA на ноутбук для этого пути устанавливать не требуется.

Сначала скачай обновлённый ZIP комплекта и открой входящий в него style_task_colab.ipynb в Colab. В блокноте уже есть код: запускай готовые ячейки по порядку. Команды ниже помогают понять, что делает каждая ячейка; повторно создавать одинаковые ячейки не нужно.

Обучение и финальные генерации в стартовом комплекте не выполнены. Они появятся после твоих запусков. В конце получишь полный архив с адаптерами и отдельный небольшой архив для загрузки на GitHub через браузер.

## 1. Подготовь рабочую папку на Windows

1. Нажми Win+D, чтобы перейти на рабочий стол.
2. Нажми правой кнопкой на свободном месте → Создать → Папку.
3. Назови её LLM_test.
4. Скачай ZIP репозитория через Code → Download ZIP.
5. Открой загрузки браузера сочетанием Ctrl+J и найди скачанный архив.
6. Перенеси его в LLM_test.
7. Правой кнопкой по ZIP → Извлечь всё → Извлечь.
8. Открой распакованную папку, затем llm-style-task.

В ней должны быть style_task_colab.ipynb, GUIDE_RU.md, train.py, generate.py и папка data/raw с тремя JSONL. Исходные файлы задания уже включены; повторно загружать их по отдельности не нужно. TXT с итоговыми постами и RESULTS.md в стартовом архиве отсутствуют — их создадут реальные запуски.

Сохрани исходный ZIP: ты загрузишь его в Colab. Если браузер добавил к имени ZIP «(1)», это не мешает первой ячейке.

## 2. Подготовь аккаунты и записывай время

Нужен Google-аккаунт для Colab и аккаунт GitHub для сдачи. Если Google-аккаунт уже есть, используй его. GitHub можно создать перед публикацией результата.

Запиши время начала работы в Блокноте Windows. В конце отчёт попросит общее фактическое время; скрипты отдельно измеряют обучение, но не время ручной проверки и подготовки репозитория.

## 3. Открой notebook в Colab

1. В Chrome открой https://colab.research.google.com/.
2. Войди в Google-аккаунт.
3. В окне открытия блокнота выбери вкладку Upload / Загрузить. Если окно закрыто: File / Файл → Open notebook / Открыть блокнот → Upload.
4. Нажми выбор файла и открой style_task_colab.ipynb из распакованной папки.
5. Дождись появления блокнота с текстом и ячейками кода.
6. Если он не сохранён в твоём Drive, выбери File → Save a copy in Drive / Сохранить копию на Диске.
7. Работай в сохранённой копии. Название можно изменить нажатием на него, например LLM_test_Qwen.ipynb.

.ipynb — файл блокнота с текстом и исполняемыми ячейками. .py — отдельный Python-скрипт. .md — текст с Markdown-разметкой. .jsonl — один JSON-объект на строку. .safetensors — файл весов модели/адаптера.

## 4. Включи облачную GPU

1. В верхнем меню выбери Runtime / Среда выполнения.
2. Открой Change runtime type / Сменить тип среды выполнения.
3. В Hardware accelerator / Аппаратный ускоритель выбери GPU. Если предлагается T4, выбери T4.
4. Нажми Save / Сохранить.
5. Нажми Connect / Подключиться справа сверху, если среда ещё не подключена.

Здесь выбирается GPU сервера Google. На ноутбуке NVIDIA не требуется. Не выбирай Local runtime / Локальную среду выполнения.

Бесплатные ресурсы Colab не гарантированы. Если появляется сообщение о недоступной GPU, повторение train.py не поможет: сначала нужно получить GPU-runtime. Основной сценарий не требует покупать тариф.

## 5. Научись запускать ячейку

У ячейки кода слева есть кнопка ▶. Нажми её или щёлкни внутри ячейки и нажми Shift+Enter. Ниже появится вывод.

Пока ячейка выполняется, кнопка выглядит как остановка/индикатор выполнения. Дождись завершения. Не запускай два обучения одновременно. Красный traceback, Exception или CalledProcessError означает ошибку; следующий зависимый этап до её устранения не запускай.

Не нажимай Run all / Выполнить всё: между вычислениями нужно вручную проверять данные и оценки.

В готовом блокноте используются команды run('имя.py', ...). Функция run определена после установки; она запускает скрипт и останавливается при его ошибке. Все эти команды выполняются в ячейках Colab, а не в PowerShell, CMD или Windows-Блокноте.

## 11. Ознакомься с решением

Используется Qwen/Qwen2.5-1.5B-Instruct и два независимых QLoRA-адаптера. Замороженная база хранится при обучении в NF4, а обучаются небольшие дополнительные матрицы. Type1 отвечает за первый стиль, type2 — за второй.

Основная конфигурация:

| Параметр | Значение |
|---|---|
| Модель | Qwen2.5-1.5B-Instruct |
| Квантизация базы | NF4, double quantization |
| Rank / alpha / dropout | 16 / 32 / 0.05 |
| Learning rate | 1e-4 |
| Эпохи | 3 |
| Batch / accumulation | 1 / 2 |
| Effective batch | 2 |
| Лимит обучающего диалога | 1024 токена |
| Gradient checkpointing | Включён |
| Seed | 42 |

При двадцати обучающих парах получается около тридцати шагов обновления на адаптер. Это стартовая конфигурация, её эффективность проверяется по текстам validation.

Чат формируется через tokenizer.apply_chat_template. System задаёт стиль и правила фактов, user содержит исходник, assistant — эталон. Loss учитывает только assistant-ответ и его завершение; system/user/padding маскированы -100. Полный шаблон и параметры сохраняются при тренировке.

## 13. Прочитай все обучающие пары

Запусти ячейку скачивания DATA_REVIEW.md. Файл попадёт в загрузки Windows. Перенеси его в LLM_test и открой в Visual Studio Code или Блокноте.

В каждом блоке указаны нейтральный исходник и целевой пост. Прочитай все пятьдесят пар. Проверь числа, имена, места, сроки, причинность, статус законопроектов и отсутствие добавленных фактов.

Первый стиль — короткий новостной текст с общественно-экономическим акцентом и возможной иронией. Второй — один эмодзи, короткий лид, пустая строка и детали простым языком. Название «финансы» не обязывает выдумывать прогнозы. Городской стиль не означает перенос любой новости в Москву.

В data/target_overrides.json уже документированы шесть предложенных правок: нижняя цена 3500 сохраняется; диапазон ставок 28–35% не подменяется конкретной ставкой и маркой смартфона; 20,4% сохраняется без округления; риск для части кофейных ферм не становится полным исчезновением кофе; средняя аренда не объявляется минимальной; адрес кофейни не придумывается. Исходные JSONL в data/raw сохранены.

Остальные пары тоже нужно проверить: список числовых предупреждений не доказывает верность смысла.

## 14. Если нужны дополнительные правки targets

Работай с data/target_overrides.json, а не с raw или processed. В файловой панели Colab открой llm-style-task → data → target_overrides.json. Скачай файл и отредактируй его в VS Code. Новая правка должна содержать id пары, source_sha256, target и reason по образцу существующих записей.

source_sha256 копируется из соответствующей записи data/processed/type1_train.jsonl, type1_val.jsonl или файла второго стиля. ID виден в DATA_REVIEW.md. Строку target записывай как JSON-строку; переносы внутри неё — через \n. После изменений файл должен оставаться корректным JSON.

Для простой проверки можно оставить предложенные шесть правок после их чтения. Если заметил дополнительное искажение, исправление нужно документировать; не обучай модель на заведомо ложной цели только ради копирования стиля.

## 22. Заполни тридцать строк оценок

В таблице первые три столбца — стиль, id и режим. Их не меняй. Заполни четыре последних столбца:

| Столбец | Какой диапазон | Смысл |
|---|---|---|
| Факты | 0 или 1 | 0 — найдено существенное искажение; 1 — не найдено |
| Стиль | 1–5 | Соответствие именно предоставленным референсам |
| Структура | 1–5 | Лид, абзацы, компактность, нужный формат |
| Язык | 1–5 | Естественность русского языка и отсутствие ошибок |

Для шкалы 1–5: 1 — явно плохо, 3 — частичное соответствие, 5 — хорошее соответствие без заметной проблемы. Оценивай каждый ответ после чтения исходника; одинаковые оценки заранее не подставляются.

Пример формы строки, не готовая оценка:

```text
| type1 | type1-010 | baseline | 1 | 3 | 4 | 4 |
```

Можно добавить заметки об ошибках ниже соответствующего текста, не меняя столбцы таблицы. Сохрани Ctrl+S. Это человеческая оценка; скрипт не делает её за тебя.

## 24. Выбери конфигурацию по validation

Посмотри сводку. Сравни adapted прежде всего с prompt-only: это показывает дополнительный эффект LoRA. Сравнение с baseline отвечает обязательному требованию до/после.

Если LoRA не улучшила результат, так и напиши в выводах. При явном ухудшении после обучения допустима одна более осторожная попытка, например --epochs 2 --lr 5e-5, но сначала сохрани предыдущий архив. После переобучения повтори adapted validation, make_review.py и ручную оценку: старые оценки к новым ответам не относятся.

Для первого прохода сохраняй основную конфигурацию, если она даёт приемлемые ответы. Не делай десятки попыток на одной маленькой validation-выборке. Финальные пять test-исходников не используются для выбора гиперпараметров.

## 25. Сгенерируй пять постов каждого стиля

## 29. Разберись с vLLM-кейсом, не устанавливая его на ноутбук

Для этого сценария vLLM не запускается в Windows или Colab. Готовая команда и расчёт уже включены в RESULTS.md и PRODUCTION.md. Они относятся к указанному в задании серверу с одной NVIDIA 24 GB.

В своём статусе можно написать, если это соответствует действительности:

«Обучение и генерации выполнены в Google Colab. Сервер с NVIDIA 24 GB для нагрузочного тестирования не использовался. Ниже приведены команда развёртывания, расчёт памяти и процедура проверки; конфигурация представляет проектный план.»

Основные значения: FP16 inference, max-model-len=4096, gpu-memory-utilization=0.85, max-num-seqs=15, max-num-batched-tokens=2048, chunked prefill, два LoRA, max-lora-rank=16. Первоначально включён enforce-eager для отключения CUDA Graphs.

Для Qwen2.5-1.5B: 28 слоёв, 2 KV-головы, размер головы 128. KV на токен FP16: 2×28×2×128×2=28 672 байта=28 KiB. На 4096 токенов — 112 MiB, на 15 последовательностей — 1680 MiB≈1,64 GiB. Это только полезный KV: отдельно веса ~2,9 GiB, LoRA, активации, runtime и запас.

Условные 24 GiB×0,85=20,4 GiB бюджету vLLM; 3,6 GiB остаётся снаружи. Это стартовая оценка, которая проверяется профилированием и длинными запросами, а не гарантия от OOM.

4096 означает промпт и ответ вместе. При 512 выходных токенах полный вход ≤3584. Если 4096 — полный вход плюс 512 ответа, нужен лимит 4608 и пересчёт. Параметр max_loras=2 относится к двум разным адаптерам в батче, не к двум пользователям. max_num_seqs=15 не ограничивает всю HTTP-очередь; очередь и backpressure задаются приложением.

Сохрани эти объяснения в отчёте. Не заявляй, что сервер успешно выдержал нагрузку, если нагрузочный тест не выполнялся.

## 38. Как восстановиться после потери Colab

Если произошёл обычный перезапуск Python, файлы обычно остаются. Выполни ячейку проверки/определения run и продолжи с нужного этапа. Первый ZIP повторно не распаковывай.

Если машина удалена и папка исчезла:

1. Открой тот же notebook и выбери облачную GPU.
2. В загрузочной ячейке выбери последний скачанный checkpoint ZIP.
3. Установи библиотеки в новую среду и перезапусти Python.
4. Выполни проверку CUDA/run.
5. Посмотри в файловой панели, какие adapters и artifacts уже восстановлены.
6. После checkpoint_type1 нужно выполнить обучение type2. После checkpoint_both_adapters можно перейти к adapted validation. Сохранённые реальные результаты не требуется создавать заново только из-за новой виртуальной машины.

## 39. Частые ошибки

| Сообщение или ситуация | Что делать |
|---|---|
| GPU недоступна | Сначала получить GPU-runtime; train.py не запускать на CPU |
| run is not defined | Повторить ячейку проверки после перезапуска |
| Папка проекта уже существует | Для продолжения не распаковывать стартовый ZIP поверх результатов |
| No such file / неверная папка | Проверить /content/llm-style-task и выполнялся ли upload проекта |
| CUDA=False | Проверить GPU-runtime и установку torch, затем перезапуск Python |
| Ошибка установки библиотеки | Не переходить к обучению; сохранить полный текст ошибки |
| CUDA OOM | Убедиться, что не запущены параллельные модели; остановившийся этап диагностировать отдельно |
| Не заполнена оценка | Исправить указанную строку REVIEW.md, загрузить снова и пересчитать сводку |
| Осталось ЗАПОЛНИТЬ | Исправить RESULTS.md, загрузить снова и повторить упаковку |
| REVIEW (1).md или RESULTS (1).md | Переименовать в точное имя перед обратной загрузкой |
| GitHub отклоняет большой файл | Использовать github_upload.zip, не полный архив с весами |

При технической ошибке скопируй последние строки traceback и укажи, какая ячейка выполнялась. Не начинай всё заново без определения причины: данные и уже обученные адаптеры могут быть сохранены.
